          BruControl Schema
          
    
          Choose a BruControl Schema file (BruControl calls it a configuration file, .brucfg, in Documents\BruControl). Its interfaces, Devices, tabs (BruControl workspaces), Widgets and processes (scripts) are brought in with their settings: pins, calibrations, PID / hysteresis / duty cycle settings, timers, alarm sounds, pictures, colors, fonts and positions.

          Testing mode
          
      
      
          While this is on, installing a new version of the panel removes every user and recovery code, so the next visit asks you to create the admin account again. Brew data, logs and settings are kept. Turn it off once you use the panel for real.
          
      
          Simulation (test mode)
          
      
          Try out a brew without touching any hardware. While it is on, every board is replaced by the simulator: processes, timers, alarms and the screen work as on brew day, but heaters, pumps and valves are only pretend. Time can run faster, and can skip ahead so you do not wait out a 60 minute mash. Turning it on or off stops every process and turns every output off.
          
      
          
        
        
        
      
          
      
          
        
        
      
          
      
          Auto skip needs no table: each step runs for the seconds above, then the clock skips to a few seconds before the next sleep end, timer wait or countdown, in every running Process (called ones and loopers too). A wait on a button or a temperature is never skipped: press the screen buttons as usual. Only time is skipped.
          
      
          Time jumps
          
      
          Skips ahead by itself in simulation mode. Example: when timer tm_Mash starts, wait 5 seconds, then jump ahead 00:50:00; the mash timer goes from 00:00:05 to 00:50:05, so a 60 minute mash takes about 15 seconds of watching.
          
      
          OnWhenNameThen wait (seconds)Jump ahead (hh:mm:ss)Note
          
      
          
      
          Process timeline
          
      
          Works out when each step of a Process happens, for example "00:10:00 into the mash: check the pH". It reads the Process without running it, using today's values. A wait on something other than a timer (a temperature, a button) cannot be known ahead, so the steps after it are timed from the end of that wait.

          MQTT and voice
          
    
          
      
          Shares vAPI variables and Devices with an MQTT broker (for example Mosquitto on the Raspberry Pi), so ESP32 boards, Node-RED or Home Assistant can read and change them. Through Home Assistant you can also ask Alexa, Google Home or Siri. Setup steps: docs/MQTT_AND_VOICE.md.
          
      
          
      
          
      
          
        
        
        
        
        
      
          
      
          
      
          Safety: MQTT and voice can always read values, silence alarms and stop processes. They can change vAPI variables that are not read-only (the same as the web API). They can only switch outputs (heat, pumps, valves), change timers or start processes that you tick below. Inputs from hardware are read only, and Shared variables are never shared.
