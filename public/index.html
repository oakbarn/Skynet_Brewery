⚙ Simulator settings

Every Simulator setting is here on the Simulator bar, and only here. Speed and Auto skip are on the bar itself and are saved as soon as they are changed.

Pretend readings are reached: a Process that waits on a reading (a temperature reaching strike temperature, the boil starting, a level, a weight or a flow total) moves on by itself after the seconds above, as if the reading got there. Skip to next event and Auto skip count it as an event. Waits on a button or a switch are never pretended.

Auto skip needs no table: each step runs for the seconds above, then the clock skips to a few seconds before the next sleep end, timer wait or countdown, in every running Process (called ones and loopers too). A wait on a button is never skipped: press the screen buttons as usual. A wait on a temperature is skipped only when Pretend readings are reached is on. Only time is skipped.

Time jumps

Skips ahead by itself in Simulator mode. Example: when timer tm_Mash starts, wait 5 seconds, then jump ahead 00:50:00; the mash timer goes from 00:00:05 to 00:50:05, so a 60 minute mash takes about 15 seconds of watching.

OnWhenNameThen wait (seconds)Jump ahead (hh:mm:ss)Note

Process timeline

Works out when each step of a Process happens, for example "00:10:00 into the mash: check the pH". It reads the Process without running it, using today's values. A wait on something other than a timer (a temperature, a button) cannot be known ahead, so the steps after it are timed from the end of that wait.

          Interfaces (boards)
          
    
          An Interface is a board (PLC) the Devices are wired to. Its ID starts the suggested name of every Device on it, for example MB_25_DO@Pump_Wort_BH. Interface IDs follow Rule 3.2.
          
    
          IDNameBoardModeConnectionRatingLost CommStatus
          
    
          Add Interface
          
    
          opens the Add Interface pop-up (the same one as "➕ Add new Interface…" in the New Device box).
          
    
          
    
          
    
          1-Wire circuits
          
    
          A 1-Wire circuit is one data pin on an Interface, with its 4.7k pull-up resistor; all its DS18B20 probes share it. An Interface can have several. Each probe has a 1-Wire Index on its circuit: BM1w1_2 = Interface BM, circuit 1, probe 2 (Rule 6.37).
          
    
          CircuitInterfacePinPowered byResolutionProbes
          
    
          
    
          1-Wire Indexes
          
    
          Each DS18B20 probe's Index holds its ROM id, and temperature Devices use the Index. To replace a probe, plug in the new one and pick its ROM id in the Index's row: every Device that uses that Index follows it, nothing else changes.
          
    
          1-Wire IndexNameProbe ROM idReadingUsed by
          
    
          OneWire probes seen
          
    
          Every probe the boards report, by its ROM id (not its position on the circuit). Give a new probe a 1-Wire Index here.
          
    
          InterfacePinProbe ROM idReading1-Wire Index
          
    
          
  
          

  
  
          
    
          BeerSmith recipe
          
    
          Choose a BeerSmith .bsmx file (BeerSmith 3 or 4: the recipe file BeerSmith saves) or a BeerXML .xml file (BeerSmith: File > Export > BeerXML; most other recipe programs export it too). It becomes the Recipe on ☰ Menu > Recipe, with every grain, hop, yeast and misc item. An .xml file also fills the Globals named in Settings > BeerXML mapping, when one is set.
          
    
    
    
          
    
          Other programs (Node-RED etc.) can POST the .bsmx or .xml file to /api/import/recipe?file=MyBeer.bsmx, or a Process can use import_recipe "Recipes/MyBeer.bsmx".

          MQTT and voice
          
    
          
      
          Shares every Device and Widget whose .API is on with an MQTT broker (for example Mosquitto on the Raspberry Pi), so ESP32 boards, Node-RED or Home Assistant can read and change them. Through Home Assistant you can also ask Alexa, Google Home or Siri. Setup steps: docs/MQTT_AND_VOICE.md.
          
      
          
      
          
      
          
        
        
        
        
        
      
          
      
          
      
          .API is the one switch for the web API, MQTT and voice, in each Device's or Widget's Properties: Off = not shared, Read Only = they can read it, Read & Control = they can also change it. Inputs from hardware are always read only. A shared alarm can always be silenced, and every process can be stopped. They can only start the processes you tick below.
